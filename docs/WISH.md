# 许愿池功能

仓颉生态榜单提供「许愿池」功能，让外部用户匿名提交希望仓颉社区建设的三方库 / 工具，并附上竞品来源，便于社区参考实现。所有许愿直接保存在站点自闭环的存储里（Cloudflare D1），不依赖 GitHub Issue。

## 使用方式

1. 打开 [在线榜单](https://rank.cangjie-lang.cc/)
2. 点击页面右上角的「许愿池」按钮（带 🎯 图标，按钮上的小徽章显示当前许愿总数）
3. 弹层会先展示**许愿清单**（默认按热度排序），可：
   - 切换排序：**热门** / **最新** / **分类**
   - 切换状态筛选：**全部** / **待实现** / **已完成** / **已拒绝**
   - 点击任意许愿卡片查看**详情**（含完整描述、竞品列表、+1 数、状态）
   - 给支持的许愿点 **+1**（同一浏览器或同一出口 IP 对同一许愿只能 +1 次）
   - 点击清单右上角的「+ 提交新许愿」按钮打开**提交表单**
4. 在表单中填写标题、描述、类别、多个竞品、可选昵称 / 邮箱
5. 填写标题时会**实时**在表单下方提示相似的已有许愿（非阻塞，仅提示）
6. 完成 Cloudflare Turnstile 人机验证
7. 点击「提交许愿」
   - 若后端检测到高相似度许愿，会返回 409，前端弹出二次确认框，可选择「取消去查看」或「坚持提交」
8. 提交成功后，新许愿会高亮出现在清单顶部

## 字段说明

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 许愿标题 | 必填 | 一句话描述你希望的库 / 工具，≤ 120 字。提交时与已有许愿做查重 |
| 详细描述 | 必填 | 使用场景、期望特性、为什么需要它，≤ 2000 字 |
| 类别 | 必填 | 库 / 工具 / 框架 / 其他 |
| 竞品 | 至少 1 个 | 一个许愿可有**多个**竞品；每行包含「名称 + 链接 + 实现语言」 |
| ├ 竞品名称 | 必填 | 已有的同类项目名称，例如 `marked` |
| ├ 竞品链接 | 必填 | 竞品仓库或官网 URL |
| └ 竞品语言 | 必填 | Cangjie / Rust / Go / Python / Java / JavaScript / TypeScript / C / C++ / 其他 |
| 昵称 | 可选 | 留空将标记为「匿名」 |
| 邮箱 | 可选 | 便于后续反馈，不会公开展示 |

## 查重机制

许愿时根据用户输入，在提交前后做两层查重：

| 阶段 | 行为 | 是否阻塞 |
|---|---|---|
| **填写时（实时）** | 标题输入框变化时调用 `/api/wishes/search`，FTS5 全文检索 + 关键词匹配，列出最多 5 条相似许愿 | 否，仅提示，用户可点击直接去查看 |
| **提交时** | 后端基于标题 / 描述做 token 重叠判断：标题重叠 ≥ 2 或描述重叠 ≥ 3 视为重复，返回 409 + 相似列表 | 是，必须用户二次确认 |

- 高相似度时弹出二次确认框，可选「取消去查看」或「坚持提交」
- 选「坚持提交」会带 `force=true` 重新提交，绕过查重直接入库

## +1 机制

- 同一浏览器（localStorage）+ 同一出口 IP（D1 唯一约束）双重去重
- 任一命中即视为已点过，按钮置灰
- 共享 IP 场景（多人走同一出口）下：不同浏览器仍可对不同许愿各自 +1，但**同一许愿同一 IP 只能 +1 一次**

## 状态流转

| 状态 | 含义 | 公开可见 |
|---|---|---|
| `pending` | 待实现（默认） | 是 |
| `done` | 已完成 | 是 |
| `rejected` | 已拒绝（暂不实现） | 是 |
| `hidden` | 管理员隐藏（含垃圾 / 违规内容） | 否，不在公开列表 / 详情 / 计数中出现 |

管理员通过 `PATCH /api/wishes/:id/status` 修改状态，请求头需携带 `X-Admin-Token` 与 `ADMIN_TOKEN` 环境变量匹配。

## 隐私声明

- **匿名性**：默认匿名提交，填写昵称会公开展示在许愿详情中
- **邮箱**：仅管理员可见，不会出现在公开许愿里，用于后续反馈进展
- **来源 IP**：不记录原始 IP，仅记录其 SHA-256 hash（加盐 SECRET_SALT），用于 +1 去重和频率限制。hash 无法反推原始 IP
- **User-Agent**：截断到 200 字符后入库，用于排查异常请求
- **Turnstile**：使用 Cloudflare Turnstile 进行人机验证，Cloudflare 会按其隐私政策处理相关数据

## 防滥用措施

为防止恶意刷量，许愿功能部署了多层防护：

| 防护层 | 说明 |
|---|---|
| 来源白名单 | 仅接受来自 `ALLOWED_ORIGIN` 的请求 |
| 人机验证 | Cloudflare Turnstile，多数情况无感通过 |
| IP 提交频率限制 | 同一 IP 每小时最多 5 次提交（`IP_RATE_LIMIT_PER_HOUR`） |
| IP +1 频率限制 | 同一 IP 每小时最多 20 次 +1（`IP_UPVOTE_LIMIT_PER_HOUR`） |
| +1 双重去重 | 浏览器 localStorage + D1 UNIQUE(wish_id, ip_hash) |
| 查重拦截 | 提交时高相似度需用户二次确认 |
| 管理员审核 | 管理员可隐藏垃圾 / 违规内容 |

## API 速查

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/wishes` | 列表（分页 + 排序 + 状态筛选） |
| GET | `/api/wishes/:id` | 详情（含竞品数组） |
| GET | `/api/wishes/search?q=xxx` | 查重（FTS5） |
| GET | `/api/wishes/count` | 徽章计数（仅公开状态） |
| POST | `/api/wishes` | 创建（带 Turnstile + competitors） |
| POST | `/api/wishes/:id/upvote` | +1（IP 去重） |
| PATCH | `/api/wishes/:id/status` | 管理员改状态（需 X-Admin-Token） |

## 功能未启用？

如果许愿按钮灰色不可点，说明管理员尚未完成 Cloudflare Worker / D1 / Turnstile 配置。部署步骤参见 [cloudflare-worker/README.md](../cloudflare-worker/README.md)。
